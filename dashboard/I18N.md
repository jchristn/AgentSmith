# Dashboard internationalization

How the Hugo dashboard handles languages, following `~/Code/Agents/requirements/I18N.md`.

## Locales

English is the source and the fallback. The twelve baseline locales are registered in `src/i18n/localeRegistry.js`:

| Code | Language | Direction | Variant | Status |
|---|---|---|---|---|
| `en` | English | LTR | | Source |
| `es` | Spanish | LTR | Neutral | Machine-seeded, needs review |
| `pt` | Portuguese | LTR | Brazilian (`pt-BR`) | Machine-seeded, needs review |
| `fr` | French | LTR | | Machine-seeded, needs review |
| `it` | Italian | LTR | | Machine-seeded, needs review |
| `de` | German | LTR | | Machine-seeded, needs review |
| `zh` | Mandarin Chinese | LTR | Simplified (`zh-Hans`) | Machine-seeded, needs review |
| `ar` | Arabic | RTL | Modern Standard Arabic | Machine-seeded, needs review |
| `ru` | Russian | LTR | | Machine-seeded, needs review |
| `ms` | Malay | LTR | Malaysia | Machine-seeded, needs review |
| `hi` | Hindi | LTR | Devanagari | Machine-seeded, needs review |
| `ja` | Japanese | LTR | | Machine-seeded, needs review |

Strings shared with Garrison reuse Garrison's translations where the English text did not change; everything else was
machine translated. Every non-English locale is marked beta in the language selector (for example "Français (bêta)")
until a native speaker reviews it. Known review items: the Spanish catalog mixes informal strings from Garrison with
formal new ones, and the German catalog uses both "Geheimnisse" and "Secrets".

Machine translated in every non-English locale and awaiting review: the analytics page keys (`views.analytics.*` and
`tips.views.analytics.*` for KPIs, metrics, columns, and tables), the model endpoint health history
(`resources.models.history.*`, `enums.modelHealthSource.*`, `tips.enums.modelHealthSource.*`), the credential owner
bypass and role (`resources.credentials.*.inheritOwnerBypass`, `resources.credentials.*.roleName`,
`resources.credentials.ownerBypass*`, `tips.badges.ownerBypass`), the session filters
(`resources.sessions.fields.userId`, `resources.sessions.fields.credentialId`, `tips.filters.credentialId`),
`enums.auditEventType.CredentialBypassChanged`, the error codes `ProviderUnreachable`, `ProviderTimeout`, and
`BypassRequiresAdministrator`, and the settings labels `Connectors.McpAllowStdio` and `Auth.PasswordHashIterations`.

Pseudo-locales are generated from English at runtime and appear in the selector only while active:

- `en-XA` (expansion): accented, bracketed, and about 35 percent longer, to catch clipped or concatenated text.
- `ar-XB` (bidi): right-to-left, to catch layouts that ignore `dir="rtl"`.

Select one with `?lang=en-XA` or `?lang=ar-XB`.

## Runtime

- `src/i18n/index.js` initializes i18next with English bundled, detects the locale (`?lang=`, then `hugo.locale` in
  localStorage, then the browser), loads that catalog, and only then renders (`main.jsx` awaits `i18nReady`), so there
  is no flash of English. Other catalogs are lazy chunks loaded by `setActiveLocale()`.
- Changing language sets `lang`, `dir`, and a per-script font stack (`--locale-font`) on `<html>`, persists the choice,
  and survives login and logout (logout never clears `hugo.locale`).
- Every request sends `Accept-Language`.
- `src/i18n/formatters.js` formats numbers, dates, times, relative times, durations, bytes, percents, and lists with an
  explicit locale through `Intl`.
- Catalogs are JSON in `src/i18n/locales/<code>.json`, one namespace (`translation`), i18next interpolation
  (`{{name}}`) and plural suffixes (`_one`, `_other`, plus `_zero`, `_two`, `_few`, `_many` where the language needs them).

## Server text

The server returns stable codes and the dashboard localizes them: `errorCodes.<code>`, `common.fieldCodes.<code>`, and
`enums.<group>.<value>` for every enum. Connector descriptors are server text (labels and help in English); a
translation under `connectors.<type>.settings.<key>.label` or `.help` wins when present, so built-in connectors can be
localized without a server change. Free-form server messages that match a known template are translated by
`src/utils/serverText.js`; anything else shows as sent.

## Glossary

Kept in English everywhere: Hugo, Agent Smith, Mr. Anderson, MCP, A2A, REST, SSE, JSON, API, URL, HTTP, SDK, OpenAI,
OpenAPI, product and provider names (Claude Code, Ollama, Anthropic, Grafana, PostgreSQL, Kubernetes, and so on),
setting paths, tool names, and environment variable names. Acronyms stay upper case. Translators use one term per
concept: tool call, approval, binding, resource, secret, tenant, profile, access mode, effect (Read, Write,
Destructive), lockdown, credential, prompt template, connector.

## Checks

`npm run i18n:check` (and the Vitest suites `i18nKeys.test.jsx`, `i18n.test.js`, `tooltips.test.jsx`,
`enumLabels.test.jsx`) fail on: a static key missing from English; a template key family with no English key; an
English key no source file can reach; a locale missing or adding keys, dropping placeholders, or leaving long English
sentences untranslated; hard-coded JSX text or `placeholder`, `title`, `aria-label`, and `alt` attributes; enum
values shown raw; and em-dashes or en-dashes. `tests/e2e/i18n.spec.js` covers language selection before and after
sign-in, persistence, every locale's navigation, Arabic RTL, and both pseudo-locales at desktop and phone widths.

## Adding a locale

1. Add an entry to `LOCALES` in `src/i18n/localeRegistry.js` (code, names, direction, aliases, beta label, font).
2. Run `npm run i18n:export`; it writes the English text of every key the new locale lacks to
   `i18n-missing/<code>.json` (create an empty `src/i18n/locales/<code>.json` first).
3. Translate, keeping placeholders, and save the result as `src/i18n/locales/<code>.json` (nested like `en.json`).
4. Run `npm run i18n:check` and `npm test`.

## Adding strings

Add the English text to `src/i18n/locales/en.json` under a stable key (`area.page.thing`, tooltips under `tips.`),
use it with `t('key')`, then add the translation to every locale; `npm run i18n:export` lists what each one lacks.
