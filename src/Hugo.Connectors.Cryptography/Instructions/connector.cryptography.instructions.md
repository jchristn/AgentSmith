# Cryptography

Use crypto_encrypt, crypto_decrypt, crypto_hash and crypto_verify_hash for local transforms. The administrator chooses the cipher and binds one AES key material secret containing key and optional salt/iv to encryptionKey in the vault. Each material field can record its own base64 or hex encoding; otherwise the resource keyEncoding applies. Legacy Generic secrets with value remain supported. Never ask users for key material, place keys in tool arguments, return keys, or record keys in context. For new encryption prefer authenticated AES-GCM. AES-CBC is explicit legacy interoperability with PKCS7 padding; it cannot establish authenticity. A plain SHA digest is an integrity comparison, not proof of authenticity unless the expected digest came from a trusted source.

The connector resolves vault secrets internally. You do not need a secret-reading tool or plaintext key/IV access to decrypt. Resource context is optional notes, not the secret store; absent or failed context retrieval does not indicate missing key material. Never search context, files or environment variables for bound secrets. When asked to decrypt with an attached resource, call crypto_decrypt before claiming its material is unavailable. If it fails, report the actual tool error and distinguish a configuration/format failure from missing bound material. Do not invent decoded byte counts.

For raw AES-CBC ciphertext encrypted with the bound material, call crypto_decrypt with data, format separate, inputEncoding base64 (or the known ciphertext encoding), and outputEncoding utf8 for text. Omit nonce and tag to use the bound AES secret iv; do not ask the user to resupply it. A single 16-byte ciphertext block is valid for a short PKCS7-padded value. Separate ciphertext need not contain a prepended IV. If the same resource decrypted another value, do not claim the bound key is inaccessible. A real failure may still indicate different producer settings; use the tool error as evidence.

Describe stable cipher/envelope/encoding conventions in resource context without secrets. Consult that context before processing blobs; do not guess formats. Retrieve encrypted objects losslessly with storage_read encoding base64, and verify truncated is false. Preserve every byte. Respect maxInputBytes and the binding output limit. These tools fail rather than return incomplete ciphertext or plaintext. Large objects require a separately supported bounded processing workflow, not arbitrary independent decryption of chunks.

Inputs default to base64 and output defaults to base64. Encrypt and hash may use utf8 input. Only decryption may produce utf8 output; use base64 for binary plaintext. Nonce/tag/associatedData use inputEncoding, and returned nonce/tag use outputEncoding. Encryption always generates fresh random nonce/IV values. GCM uses a 12-byte nonce and 16-byte authentication tag. Combined format is nonce || ciphertext || tag for GCM, or IV || ciphertext for CBC. Separate format takes nonce (also the CBC IV) and tag as individual arguments. Separate CBC decryption uses an explicit nonce first, then the AES bundle iv, then a legacy initializationVector secret. keyDerivation None (the default) uses the decoded key directly and does not apply the optional salt. Explicit PBKDF2-SHA256 derives the AES key from the decoded key/password and salt using administrator-configured iterations and derivedKeyBytes. Never infer derivation parameters from the presence of salt. No implicit JSON unescaping, algorithm detection, or IV guessing is performed.

Plaintext returned by decryption is sensitive data visible to this agent through its normal authorized tool output. Reveal only what is needed for the user's task. Do not copy decrypted confidential data into durable context. All operations are Read effects because they transform data locally without changing remote resources.
