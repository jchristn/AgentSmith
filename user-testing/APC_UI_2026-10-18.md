# Agent document dashboard verification

Date: 2026-10-18. Base commit: `8354ba0cc0082ec6c8b57d9147a8daeb61e0ca18`; working tree included the uncommitted document feature and background-chat changes. Platform: Darwin arm64, Node.js v24.21.0, npm 11.19.0. Product version remains `0.1.0-alpha`.

This report covers dashboard implementation checks using deterministic synthetic HTTP fixtures. It is not a claim that the complete isolated deployment, live model behavior, SDK live harnesses, migration or cross-tenant authorization were verified by this session. Those checks belong to the feature’s backend and release evidence.

## Environment and users

Playwright built the production dashboard and served it at `http://127.0.0.1:4173`. HTTP fixtures supplied fake administrator identity, synthetic document content, immutable revision metadata and versioned attachments. No production service, inference provider, credential or resource was used. Test-browser contexts were discarded afterward; the Playwright preview server exited with the runner. No test database or Docker service was created.

The simulated operator imports a local document, reviews its Markdown, attaches it to an agent, pins its revision, previews delivery, and detaches it. Additional component scenarios represent an editor resolving a concurrent save and a caller requesting public preview without supplying arbitrary credential identity.

## Findings and limitations

No unresolved defect was found in the exercised journeys. This does not imply untested backend authorization or persistence is correct. The mock suite cannot prove SQL transactions, grant revocation, server-enforced limits, restart behavior, actual model consultation, or publication credential readiness.

During implementation, the library’s server sort request was aligned to Hugo’s existing `ordering=NameAscending|NameDescending` contract. Public audience controls and versioned requests use the feature’s documented API shapes. These implementation corrections are covered by the resulting UI and transport tests rather than presented as independent user-testing findings.

This report introduces no approval requirement and no production change. A full isolated cross-surface session remains a release gate in `ADDITIONAL_PROMPT_CONTEXT.md`.

After the mocked checks, a real local Hugo process was started by the integration owner with a fresh scratch SQLite database, synthetic seeded users and no existing user data. API: `http://127.0.0.1:18880`; dashboard: Vite at `http://127.0.0.1:18881`, proxying that API. No request interception or API mocks were used for this follow-up. The setup wizard was marked dismissed to focus on document management; the seeded password advisory was skipped in each test tab. A temporary agent was created as setup through the API; document creation and subsequent document/attachment operations were driven through the dashboard.

The actual browser journey passed:

1. Sign in as the synthetic seeded administrator.
2. Import `LOG_MESSAGE_STRUCTURE.md`, review literal Markdown braces, save and read the persisted document.
3. Attach it as Reference. Confirm the real compiled preview contains its catalog entry without the body.
4. Open its editor and inspect the actual agent referrer.
5. Open the document in two tabs. Save one revision, submit the stale second editor and verify HTTP 409 preserves its draft.
6. Switch the attachment to Inline and verify the preview resolves the latest persisted body.
7. Detach through the dashboard, delete the document through the dashboard and delete the temporary setup agent.

The successful journey removed its temporary records. Failed harness attempts also removed their exact temporary profile/document records. No test data was left intentionally. The integration owner retains responsibility for the scratch API process and database while other release checks run. The feature-specific Vite process is stopped after this session.

### APC-UI-001: New-document modal used the update path

- **Severity:** S1, core creation journey could not complete.
- **Category:** Defect.
- **Surface/user:** Dashboard, administrator creating a document.
- **Oracle:** Feature plan section 6 requires document creation to use POST without an existing-version token.
- **Reproduction:** Open Instructions → Documents → Add document, enter required fields, Save.
- **Observed:** The library passed an empty object for a new draft; the editor treated that object as an existing record and attempted an update without an ID/version. The server rejected it.
- **Expected:** POST creates revision 1 and returns the stored document.
- **Decision:** Addressed within the authorized feature implementation.
- **Correction:** Existing-document state now requires an actual ID. A regression component test supplies the same empty-object draft; the browser test also asserts the create-modal title and POST request method.
- **Verification:** The complete real-server journey above passed after the correction. Existing mocked browser checks alone had not detected the request-method mismatch, so those assertions were strengthened.

The Postman collection now includes a self-contained **Agent prompt documents** folder with 21 documented API requests, captured concurrency variables, revision/content reads, referrers, both delivery modes, atomic reorder, stale-write and in-use-delete rejection, detach and cleanup. Newman executed the folder against the same scratch server: **23 HTTP requests including two sign-ins, 26 assertions, zero failures**, approximately 458 ms. The sanitized summary is `user-testing/evidence/APC-live/postman-summary.json`; raw authentication responses are not included in committed artifacts.

Reproduce that folder against an isolated server with the normal seeded test users and `scripts/newman.sh --folder 'Agent prompt documents'`; override `HUGO_PORT`, `HUGO_EMAIL`, and `HUGO_ADMIN_EMAIL` when using alternate scratch settings. Do not point this mutating journey at a production tenant.


## Bounded local-model smoke

A live inference follow-up used the locally available `qwen3:8b` model through an isolated temporary endpoint/profile. The agent was limited to four iterations and four tools; the endpoint allowed 768 output tokens and a 120-second request timeout. The synthetic document defined a private test convention: triage code R7 means cache rebuild completed, followed by an exact 23-second wait. The natural user request asked the agent to interpret that event using its attached guidance; it did not name or force a tool call.

Reference preview correctly omitted the body. The Reference turn returned the runtime fallback answer after approximately 41.9 seconds, with **no recorded document read and no correct interpretation**. The cause was not established by this test; the small output budget and reasoning behavior are possible factors, not a proven diagnosis. This run does not establish successful Reference orchestration for that model/configuration.

A fresh Inline conversation answered the distinctive cache/23-second fact correctly in approximately 7.3 seconds without a document read, as expected for inline content. Its generated evidence-style markup is model output, not proof of an executed tool call. The observed tool records remain the source of truth.

All temporary conversations, profile, document and model endpoint were deleted. Sanitized evidence is in ignored `user-testing/evidence/APC-live/model-smoke.json`; it records model name, timings, answer and observed tools without inference addresses or credentials. This limited model result must not be presented as universal compliance with retrieval guidance.

A second bounded run used the locally available non-reasoning `qwen2.5:7b` model, with a 1536-token output budget and the same four-iteration/four-tool ceiling. It created a fresh synthetic document defining **K4 as successful archive-index rotation, requiring exactly 37 seconds before comparing health**. This fact differed from the previous run and appeared only in the managed document. The natural prompt asked for interpretation using attached log-format guidance without naming a tool or forcing its arguments.

**Reference succeeded in approximately 23.7 seconds.** The persisted sequence was user request → assistant `agent_read_document` call → successful Tool result containing revision 1 → final answer with the correct archive-index/37-second interpretation. The call was recorded at iteration 1 with `isError=false`. The compiled Reference preview had excluded the body beforehand. This provides actual model-driven retrieval evidence for this configuration.

The fresh Inline conversation also answered correctly in approximately 2.5 seconds, but this model chose to read the document again. Its success must not be described as avoiding retrieval. The earlier `qwen3:8b` Inline conversation did answer correctly with zero tools. Together these observations verify both delivery paths while demonstrating that model decisions and redundant reads vary by configuration.

All temporary records were again removed successfully. Sanitized evidence for the successful retrieval run is `user-testing/evidence/APC-live/model-smoke-qwen25.json`. It contains model name, timings, messages and tool ordering; it contains no inference address or credentials. The earlier low-budget Reference failure remains recorded rather than being replaced by the passing run.
